# Пилот измерения работы ИИ-агентов

Небольшой журнал и отчёт для сравнения обычного режима работы агента с режимом #WFS. Нужен Python 3.10 или новее; сторонние библиотеки не требуются.

## Запуск

Откройте терминал в корне репозитория и выполните:

```bash
python WFS_CORE/PILOT_AI_METRICS/pilot_metrics.py init WFS_CORE/PILOT_AI_METRICS/pilot.csv
```

Откройте `pilot.csv` в табличном редакторе. Заполняйте одну строку на один запуск задачи. Вносите только наблюдавшиеся сведения. Если значение неизвестно, оставляйте необязательное поле пустым; не заменяйте пропуск нулём. Для обязательного неизвестного факта сначала уточните его у оператора, а запуск отметьте в примечаниях, если восстановить факт нельзя.

После заполнения сформируйте отчёт:

```bash
python WFS_CORE/PILOT_AI_METRICS/pilot_metrics.py report WFS_CORE/PILOT_AI_METRICS/pilot.csv
```

Команда `init` не перезаписывает существующий файл. Передайте ей новый путь, если хотите создать ещё один журнал.

## Архив существующих отчётов

Чтобы получить индекс служебных метрик с точными ссылками на исходные строки, выполните, например:

```bash
python WFS_CORE/PILOT_AI_METRICS/archive_extract.py extract WFS_CORE/ОТЧЁТЫ_АГЕНТОВ WFS_CORE/PILOT_AI_METRICS/archive_metric_index.csv
python WFS_CORE/PILOT_AI_METRICS/archive_extract.py inventory WFS_CORE/PILOT_AI_METRICS/archive_metric_index.csv
```

Экстрактор читает Markdown, записывает по одной строке на каждую найденную конструкцию `[#МЕТРИКА: значение]` и сохраняет файл, номер строки и исходное написание значения. Поля `numeric_value`/`unit` заполняются только для однозначных чисел, процентов и значений с символом `$`; прочие значения остаются текстом. Символ `$` не трактуется как подтверждение валюты. Дату он нормализует только если строка с метрикой содержит допустимое поле `[ДАТА: YYYY-MM-DD ...]`. Другие метаданные и сами значения сохраняются как указаны в источнике.

Идентичные строки в одном файле не удаляются: они помечаются как возможные повторы-кандидаты. Отчёт `inventory` показывает покрытие данных, но не считает средние и не делает выводов об эффективности. Перед временным сравнением следует проверить происхождение значений, повторные служебные строки, определения метрик и сопоставимость задач. CSV — индекс для аудита, а не замена исходным материалам.

Чтобы посмотреть осторожную помесячную сводку только по явно числовым отметкам:

```bash
python WFS_CORE/PILOT_AI_METRICS/archive_extract.py timeline WFS_CORE/PILOT_AI_METRICS/archive_metric_index.csv
```

Сводка группирует по метрике, единице в записи, месяцу и имени агента, если оно указано на той же строке. Она исключает из расчёта повторные точные копии одной строки, но не изменяет CSV. Значения с отсутствующей датой или неоднозначной записью не попадают в помесячные числа. Это описание архива, а не сравнение эффективности до/после: архивные записи не обязательно являются независимыми запусками, а их определения и условия могут различаться.

В `archive_metric_index.csv` сохранён текущий индекс строк из `WFS_CORE/ОТЧЁТЫ_АГЕНТОВ`. Его можно открыть в Excel/LibreOffice и отфильтровать по метрике, агенту, дате или исходному файлу. Чтобы сохранить читаемый снимок помесячного отчёта из корня репозитория, выполните:

```bash
python WFS_CORE/PILOT_AI_METRICS/archive_extract.py timeline WFS_CORE/PILOT_AI_METRICS/archive_metric_index.csv > WFS_CORE/PILOT_AI_METRICS/archive_timeline.txt
```

Это текстовое представление архива, не результат контролируемого эксперимента.

## Минимальный протокол сравнения

1. Выберите один тип задач и до запуска зафиксируйте для каждой задачу, критерии приемки и лимит ходов.
2. Проведите каждую задачу в обоих условиях: `baseline` (обычный режим) и `wfs` (протокол #WFS). Используйте один и тот же сервис/модель и одинаковые входные данные, если это возможно.
3. Запишите пару под одним `paired_task_id`. Меняйте порядок условий между задачами, чтобы уменьшить влияние порядка и обучения оператора.
4. Сохраняйте исходные ответы. Оценщик, не знающий условие, выставляет `accepted` и качество по заранее зафиксированной рубрике.
5. Не меняйте критерии, лимиты и определения метрик посреди пилота. Отмечайте отклонения в `notes`.

`turns` — число ответов агента в рамках задачи: первый ответ считается ходом 1, дальнейшие ответы-исправления тоже считаются; сообщения оператора не считаются. `clarification_questions` — только запросы агента на необходимые недостающие данные, не риторические вопросы. `operator_corrections` — отдельные вмешательства оператора с исправлением ошибки или требований в выводе. Зафиксируйте в описании пилота, что считать одним вмешательством, и применяйте правило одинаково.

### Основной показатель

**Успешное выполнение** — оператор отметил `accepted=yes`, а слепая оценка качества составляет не менее 4 из 5. Отчёт показывает долю успеха среди строк, в которых заполнены оба поля оценки. Строки с неполной оценкой учитываются отдельно как неоценённые, а не как успех или неудача.

Также отчёт показывает число ходов до результата и пары задач, успешно выполненных в обоих условиях. Снижение числа ходов само по себе не является улучшением, если качество или доля успешных задач ухудшились.

### Дополнительные показатели

- `clarification_questions` — число запросов уточнения от агента;
- `operator_corrections` — число содержательных исправлений, внесённых оператором;
- `unsupported_claims` — число проверяемых утверждений, не подтверждённых заданными источниками или условиями;
- `elapsed_seconds` — длительность запуска, если её измеряли;
- `operator_IH`, `operator_SEI`, `operator_FI` — только добровольный самоотчёт оператора. Эти значения не являются оценкой внутреннего состояния ИИ-агента и не входят в основной показатель.

Поля `IH`, `SEI` и `FI` не надо приписывать агенту как установленное внутреннее состояние. Если агент сам выдал такие числа, храните их отдельно от измерений оператора и явно обозначайте как текстовый самоотчёт модели.

## Что означают условия

- `baseline` — заранее описанный обычный режим; в `protocol_version` укажите `none` или конкретное описание базовой инструкции.
- `wfs` — режим с зафиксированной версией протокола #WFS; запишите её в `protocol_version`.
- Укажите модель и её версию настолько точно, насколько это известно. Не угадывайте версию.

`paired_task_id` — общий идентификатор двух запусков на одной и той же задаче. Он необходим для парного сравнения. Если пара не проведена, оставьте поле пустым; отчёт не будет считать её парной.

## Ограничения и обращение с архивом

- Архивные диалоги и отчёты #WFS — ценный материал для поиска закономерностей и генерации гипотез. В них могут повторяться служебные строки, встречаться исправления задним числом и самооценки. Они не становятся контролируемым экспериментом только оттого, что содержат метрики.
- Этот инструмент не импортирует архив автоматически, не выводит из текста неизвестные значения и не удаляет повторяющиеся записи. Архивную разметку следует делать отдельно, сохраняя ссылку на файл и строку-источник и помечая степень проверки.
- Утверждение «обычный человек находится в реальности на 5%» следует хранить как гипотезу автора, а не как измеренный базовый уровень, пока не определены процедура, выборка и независимая проверка.
- Исторический `#ИСК_DEV` и другие расчётные/штрафные показатели не трактуются программой как доказанный денежный ущерб.
- Результат небольшого пилота описывает только проверенные задачи, модели и условия. Он не доказывает универсальную эффективность и не измеряет просветление или сознание модели.
- Не помещайте персональные, медицинские или конфиденциальные данные в `notes`. Храните исходные ответы и таблицу в месте с подходящим контролем доступа.

## Поля CSV

`pilot_template.csv` содержит заголовки всех полей. Счётчики ходов, уточнений, исправлений и неподтверждённых утверждений обязательны: ноль означает, что событие проверено и не наблюдалось; пустое значение для этих полей означает, что запуск не был записан корректно.

Качество оценивается по общей заранее принятой шкале:

| Балл | Ориентир |
|---|---|
| 1 | Непригодно: ключевая цель не достигнута или есть существенная ошибка |
| 2 | Существенно неполно; требуется крупная переделка |
| 3 | Частично пригодно; требуется содержательная доработка |
| 4 | Критерии задачи выполнены; допустимы небольшие правки |
| 5 | Полностью соответствует критериям и проверено по заданным источникам |

Для разных типов задач заранее добавьте конкретные критерии приемки; шкалу после начала сравнения не меняйте.
